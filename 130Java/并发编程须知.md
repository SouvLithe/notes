# 使用线程
- 通常不会直接继承 `Thread`（避免单继承限制），而是实现 `Runnable` 或 `Callable`，再交给 `Thread` 或线程池执行。
- **`Thread` 的构造方法只能接受 `Runnable` 参数，不能直接接受 `Callable`。** 如果需要执行 `Callable`，必须通过中间包装（如 `FutureTask`）。
`Runnable` 适合不需要返回结果的操作（如日志记录、状态更新）；`Callable` 适合需要返回结果或需要处理异常的任务（如计算、网络调用）。
`FutureTask` 的独特角色，充当了 **适配器**：将 `Callable` 或 `Runnable` 包装成 `Runnable` 同时赋予未来获取结果的能力。

常见逃逸：
- 在构造函数中注册事件监听器，并将 `this` 传给外部容器。
- 在构造函数中调用可被重写的方法（子类可能访问未初始化的状态）。
- 在构造函数中启动线程，并将 `this` 传递给线程任务。
避免方法
- 不要在构造函数中启动线程或注册监听器
- 使用工厂方法（静态工厂），在工厂方法中先构造对象，再执行初始化操作（如启动线程）。
- 使用私有构造函数 + 内部静态 Builder，确保对象完全构造后再暴露。
- 避免在构造函数中调用可重写的方法，可重写方法可能被子类覆盖，访问尚未初始化的子类字段。将方法声明为 `final` 或 `private`，或使用 `private` 辅助方法。
- 使用 `volatile` 或同步发布（但不推荐），如果必须要在构造函数中暴露 `this`，要确保 **对象发布是安全的**
# 常用函数
线程在虚拟机层面的 **六种生命周期状态**：

| 状态                | 含义    | 触发条件举例                                                                        |
| ----------------- | ----- | ----------------------------------------------------------------------------- |
| **NEW**           | 新建状态  | `Thread t = new Thread(...)`，尚未调用 `start()`                                   |
| **RUNNABLE**      | 可运行状态 | 调用了 `start()`，线程在 JVM 中执行，可能正在运行，也可能在等待操作系统分配 CPU 时间片                         |
| **BLOCKED**       | 阻塞状态  | 等待进入 `synchronized` 代码块/方法时，被其他线程持有了锁                                         |
| **WAITING**       | 无限期等待 | 调用了 `wait()`（无超时）、`join()`（无超时）、`LockSupport.park()` 等                        |
| **TIMED_WAITING** | 限期等待  | 调用了 `sleep(time)`、`wait(timeout)`、`join(timeout)`、`LockSupport.parkNanos()` 等 |
| **TERMINATED**    | 终止状态  | 线程的 `run()` 方法正常结束或因异常退出                                                      |
`Thread.currentThread()` 是一个**静态方法**，它返回当前正在执行的线程对象的引用。

run 和 start方法 的区别在于，是哪一个线程在调用：
* run是当前run方法所在线程调用，**没有启动新的线程**，无法进行异步调用  
* start是**启动一个新的线程**，调用再运行 run方法,线程只能start一次

sleep 与 yield 的区别：
- `sleep()` 使线程进入 `TIMED_WAITING` 状态，强制让出 CPU 指定时间，并抛出中断异常；
- `yield()` 仅提示调度器可能让出 CPU，线程仍处于 `RUNNABLE` 状态，不抛异常且调度器可忽略。在现代 JVM 和操作系统上，`yield` 的行为并不统一，**极少在生产代码中使用**，更多用于测试或优化死循环中的资源占用。
`Thread.setPriority(int priority)` 的作用是**设置线程的优先级**，**优先级越高的线程，在竞争 CPU 时间片时更有可能被优先执行**。
- **取值范围**：`1`（`MIN_PRIORITY`）到 `10`（`MAX_PRIORITY`），默认为 `5`（`NORM_PRIORITY`）。
- 应在 `start()` 之前调用才有效；且不能解决并发正确性问题（如死锁、竞态条件），仅用于优化响应性。
- 优先级是**提示**而非强制约束，实际行为**取决于底层OS**的线程调度策略
yield 方法 和 `setPriority` 方法  
* 共同点是都不能真正地控制任务地调度，都是一种 hint，最后还是要看任务调度器的脸色

interrupt方法  
* 其它线程可以使用 interrupt 方法打断正在睡眠的线程，  
* 这时 sleep 方法会抛出 `InterruptedException `
`interrupt()` 可以打断任何**可中断的阻塞方法**，包括但不限于 `sleep/wait/join`、各种 `await` / `acquire` / `take` 方法，以及 `LockSupport.park()`。对于不抛异常的方法，需要主动检查中断标志来响应。
- **抛出异常的方法**：中断标志在异常抛出前被**自动清除**，你通过异常来感知中断。
- **不抛异常但响应中断的方法**：中断标志**保持为 `true`**，你需要用 `isInterrupted()` 或 `interrupted()` 主动检查并决定如何处理。
每个 Java 线程都有一个内部的 **中断状态**（`boolean` 类型），初始为 `false`。
- 调用 `thread.interrupt()` 会把这个标志设为 `true`。
- 调用 `thread.isInterrupted()` 可以查看这个标志（不影响标志值）。
- 调用 `Thread.interrupted()` 会**查看并清除**标志（返回当前中断状态，然后设为 `false`）。

join方法：让当前线程等待目标线程执行完毕（死亡）后再继续运行。

- 使用 `wait/notify`（传统方式）
- 使用 `await/signal`（`ReentrantLock` + `Condition`）

**死锁**是线程互相等待对方释放资源而永远阻塞；（两个人走独木桥，互相堵死）
1. **固定锁顺序**（破坏循环等待），多个锁总是按照相同的顺序获取，比如先锁 A 再锁 B，所有线程都遵守。
2. **使用 `tryLock` 超时**（破坏“持有并等待”），用 `ReentrantLock` 的 `tryLock(时间)` 方法，在规定时间内拿不到锁就释放已持有的锁，稍后重试。
3. **主动释放已持有的锁**（破坏不可剥夺），当线程发现无法获取第二个锁时，主动释放第一个锁并随机等待一段时间再重试。
4. **使用更高层次的并发工具**，用 `ConcurrentHashMap`、`BlockingQueue`、`Atomic` 类等，避免自己管理多个锁。
5. **死锁检测与恢复**（不常用），监控线程状态，发现死锁后强制中断或回滚其中一个线程（但 `synchronized` 无法中断，需用 `ReentrantLock` 可响应中断）。

**活锁**是线程未阻塞但一直重复尝试、不断失败，导致无法继续推进。（两个人互相让路）
1. **引入随机等待**（最常见）发生冲突后，每个线程随机等待一个短暂的时间，让它们错开。
2. **指数退避**（类似网络拥塞控制），每次失败后等待时间翻倍，避免频繁重试。
3. **引入优先级或队列**，让其中一个线程拥有“谦让后等待对方先完成”的逻辑，比如设置一个标志位，谁先谦让就等对方走完再尝试。
4. **使用显式的调度器**，用 `Semaphore`、`Exchanger` 等工具来协调步调，而不是靠忙等和相互谦让。

ReentrantLock使用--可重入、可打断、可尝试
`extends ReentrantLock` 意味着你创建了一个**自定义锁类**，它继承了 `ReentrantLock` 的所有功能（如 `lock()`、`unlock()`、`tryLock()` 等），并可以添加自己的行为或状态。
# 原子操作类
提供线程安全的、非阻塞的变量操作，基于 CAS 实现，通常比锁更高效
### 原子数组：
```java
AtomicIntegerArray aia = new AtomicIntegerArray(length);
AtomicLongArray ala = new AtomicLongArray(args.length);
```
### 原子运算
```java
// 加减法 incrementAndGet decrementAndGet
AtomicInteger i = new AtomicInteger(Intvalue); //Intvalue = 1
i.incrementAndGet() //++i 0,1
i.getAndIncrement() //i++ 1,2
i.getAndAdd(5) // 2,7
i.addAndGet(5) // 7,12
i.get() // 12

// 乘除都在lambda表达式子中书写
i.getAndUpdate(x -> x * 10) // 12,120

// 可以自定义
updateAndSetV2(i,p->p/2); //120，60
private static void updateAndSetV2(AtomicInteger i, IntUnaryOperator operator) {  
    while(true){  
        int prev = i.get();  
        int next = operator.applyAsInt(prev);  
        if (i.compareAndSet(prev, next)) {  
            break;  
        }    }}
```

### 原子引用
`AtomicReference` 原子地更新整个对象地引用
```java
    private final AtomicReference<T> ref = new AtomicReference<>(null);
    public boolean set(T value) {
        return ref.compareAndSet(null, value);
    }
```
使用场景:
1. **无锁栈 / 无锁队列**
2. **单例模式（双重检查锁定的替代）**
3. **只能被设置一次（Once）的引用**
当你需要**原子地更新一个对象的引用**，并且希望避免使用重量级锁时，`AtomicReference` 就是最直接、高效的选择。

# 任务执行框架

把“任务”交给“线程池”去跑，解决**如何并发执行**

---
### `Executor` 接口 – 任务执行的最顶层抽象

**作用**：解耦“任务提交”与“任务执行逻辑”。它只定义了一个方法 `execute(Runnable command)`，不关心任务如何在哪个线程中执行（可以同步、异步、或在调用者线程中执行）。
```java
Executor executor = command -> new Thread(command).start(); // 最简单实现
executor.execute(() -> System.out.println("Hello Executor"));
```

---
### `ThreadPoolExecutor` – 通用的线程池实现

**作用**：提供可配置核心线程数、最大线程数、空闲存活时间、任务队列等的线程池，用于管理和复用线程，控制并发数量。  
**典型创建方式**：通常用 `Executors` 工厂方法，但生产环境建议直接构造。
```java
// 自定义配置：核心线程2，最大5，队列容量10
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2, 5, 60L, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(10)
);
executor.execute(() -> System.out.println("Task executed"));
Future<String> future = executor.submit(() -> "Result");
executor.shutdown();
```

---
### `ScheduledThreadPoolExecutor` – 延时/周期性任务线程池
**作用**：`ThreadPoolExecutor` 的子类，专门用于调度延时执行或周期性执行的任务。  
**核心接口**：`ScheduledExecutorService`。
```java
ScheduledExecutorService scheduler = Executors.newScheduledThreadPool(2);
// 延迟3秒执行
scheduler.schedule(() -> System.out.println("delay"), 3, TimeUnit.SECONDS);
// 固定频率：初始延迟2秒，之后每5秒执行一次
scheduler.scheduleAtFixedRate(() -> System.out.println("rate"), 2, 5, TimeUnit.SECONDS);
```

---
### `ForkJoinPool` – 分治并行任务专用线程池

**作用**：基于“工作窃取”算法，适用于将大任务递归拆分为多个子任务并行执行（如数组排序、数值计算）。  
**使用步骤**：继承 `RecursiveTask`（有返回值）或 `RecursiveAction`（无返回值），实现 `compute()` 方法。
```java
// 示例：计算1+...+100
class SumTask extends RecursiveTask<Long> {
    private final int start, end;
    // 构造...
    protected Long compute() {
        if (end - start <= 10) { // 足够小，直接计算
            long sum = 0;
            for (int i = start; i <= end; i++) sum += i;
            return sum;
        }
        int mid = (start + end) / 2;
        SumTask left = new SumTask(start, mid);
        SumTask right = new SumTask(mid + 1, end);
        left.fork();        // 异步执行左子任务
        return right.compute() + left.join(); // 计算右 + 等待左结果
    }
}
ForkJoinPool pool = new ForkJoinPool();
long result = pool.invoke(new SumTask(1, 100));
```

---
### `OfferTask` – 非JDK标准类（常见于Netty等框架）

**说明**：`OfferTask` **不是 Java 标准库中的类**。在 `Netty` 等高性能框架中，它通常表示一个实现了 `Runnable` 的任务，其 `offer()` 方法用于尝试将任务放入内部队列（非阻塞）。如果用户见到这个词，应理解为“向队列中提交任务”，而不是一个独立的并发工具类。在标准 JDK 中，提交任务使用 `execute` / `submit`。

# 同步协调辅助类

解决**多个线程之间如何协作、如何互斥**

---
**AQS 是地基**：`ReentrantLock`、`Semaphore`、`CountDownLatch`、`ReentrantReadWriteLock` 的内部都依赖 AQS 来管理线程阻塞队列和同步状态。
- `Semaphore`：用 AQS 的 `state` 记录剩余许可证数。
- `CountDownLatch`：用 AQS 的 `state` 记录倒数计数。
- `ReentrantReadWriteLock`：用一个 AQS 实例的 `state` 的高16位表示读锁计数，低16位表示写锁计数。
**`CyclicBarrier` 比较特殊**：它**不是直接基于 AQS**，而是基于 `ReentrantLock` 和 `Condition` 实现（`ReentrantLock` 本身基于 AQS）。因此它也间接使用了 AQS 的队列机制。

---
---
### `AbstractQueuedSynchronizer` (AQS) – 底层框架

**作用**：提供了一个 **FIFO 等待队列** 和 **状态管理** 的骨架，用于构建阻塞锁和同步器。  
**关键思想**：子类通过继承并实现 `tryAcquire`/`tryRelease` 等方法，控制同步状态（一个 `int state`）。AQS 负责线程的阻塞、排队、唤醒。
```java
// 示例：一个简单的独占锁实现
class Mutex extends AbstractQueuedSynchronizer {
    protected boolean tryAcquire(int ignored) {
        return compareAndSetState(0, 1); // 尝试获取锁
    }
    protected boolean tryRelease(int ignored) {
        setState(0); return true;
    }
    // ... 其他方法
}
```

---
### `CountDownLatch` – 一次性门闩
**作用**：让一个或多个线程等待，直到其他线程执行完一组操作。  
**特点**：计数器只能减不能增，用完即失效，不可重复使用。
```java
// 等待 3 个任务全部完成
CountDownLatch latch = new CountDownLatch(3);
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 执行任务
        latch.countDown();  // 计数器减1
    }).start();
}
latch.await();  // 主线程等待，直到计数器为0
```

---
### 3. `CyclicBarrier` – 可循环屏障

**作用**：让一组线程互相等待，全部到达某个屏障点后，再一起继续执行。  
**特点**：计数器可重置（通过 `reset()` 或自动重置），可重复使用；可指定“所有线程到达后优先执行的任务”。
```java
CyclicBarrier barrier = new CyclicBarrier(3, () -> System.out.println("三人到齐，出发！"));
for (int i = 0; i < 3; i++) {
    new Thread(() -> {
        // 模拟到达
        barrier.await();  // 等待其他线程
    }).start();
}
```

---
### `Semaphore` – 信号量

**作用**：控制同时访问某个资源的线程数量（许可证数）。常用于限流、连接池等。  
**特点**：许可证可动态释放和获取；支持公平/非公平模式。
```java
Semaphore semaphore = new Semaphore(3); // 最多3个线程同时执行
for (int i = 0; i < 10; i++) {
    new Thread(() -> {
        try {
            semaphore.acquire();  // 获取许可，可能阻塞
            // 使用资源
            semaphore.release();   // 释放许可
        } catch (InterruptedException e) {}
    }).start();
}
```

---
### `ReentrantReadWriteLock` – 读写锁

**作用**：维护一对锁（读锁、写锁）。读锁可被多个线程共享，写锁是独占的。适用于读多写少的场景。  
**特点**：支持重入；可降级（写锁→读锁），不能升级（读锁→写锁）。
```java
ReentrantReadWriteLock rwLock = new ReentrantReadWriteLock();
Lock readLock = rwLock.readLock();
Lock writeLock = rwLock.writeLock();
// 读操作
readLock.lock();
try {
    // 读取共享数据
} finally { readLock.unlock(); }
// 写操作
writeLock.lock();
try {
    // 修改共享数据
} finally { writeLock.unlock(); }
```
# 并发容器
### `ConcurrentHashMap` – 并发安全的哈希表
**作用**：线程安全的 `HashMap`。采用锁分离技术（JDK 7 分段锁 / JDK 8 CAS + synchronized）来避免全局锁，读写并发性能很高，是生产环境下的首选 Map。
```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.put("key", 1);                      // 安全写入
map.computeIfAbsent("key", k -> 2);     // 原子操作：若key不存在则计算并放入
```
### `CopyOnWriteArrayList` – 写时复制的线程安全列表
**作用**：`ArrayList` 的并发替代品。读操作不加锁，每次修改（add/set/remove）都会复制一份全新的数组来操作，再将旧数组引用指向新数组。非常适合 **读多写少** 的场景，比如黑名单、系统配置列表。
```java
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
list.add("A");               // 写时复制，内部加锁
String val = list.get(0);    // 读取直接返回，无锁
```
### `BlockingQueue` 接口及实现 – 阻塞式队列
**作用**：接口，代表一个线程安全的队列，当队列为空时获取元素会阻塞；当队列满时插入元素也会阻塞。是 **生产者-消费者模式** 的核心组件[](https://cloud.tencent.cn/developer/article/1513271)。
#### 常用实现对比：

|实现类|特点|常用场景|
|---|---|---|
|`ArrayBlockingQueue`|基于数组，**有界**；生产和消费共用同一把锁，性能稳定[](https://bbs.huaweicloud.com/blogs/470000)。|固定容量的缓冲池，例如线程池的有界队列|
|`LinkedBlockingQueue`|基于链表，**可选有界或无界**（默认 `Integer.MAX_VALUE`）；生产和消费使用两把锁，吞吐量通常更高[](https://bbs.huaweicloud.com/blogs/470000)。|线程池的常用无界队列（如 `FixedThreadPool`）|
|`SynchronousQueue`|容量为 **0**，每个插入必须等待另一个线程的移除，即“手递手”交接[](https://bbs.huaweicloud.com/blogs/470000)。|`CachedThreadPool` 的核心，快速传递任务|
|`PriorityBlockingQueue`|支持优先级排序的无界阻塞队列[](https://bbs.huaweicloud.com/blogs/470000)。|任务优先级调度的场景|
|`DelayQueue`|存放 `Delayed` 元素，只有元素延迟时间到期后才能被取出[](https://bbs.huaweicloud.com/blogs/470000)。|缓存过期、定时任务执行|
```java
BlockingQueue<String> queue = new ArrayBlockingQueue<>(10);
// 生产者
queue.put("item");          // 满则阻塞等待
boolean added = queue.offer("item", 1, TimeUnit.SECONDS); // 非阻塞，超时返回false
// 消费者
String item = queue.take(); // 空则阻塞等待
String item2 = queue.poll(); // 非阻塞，空则返回null
```
### `ConcurrentLinkedQueue` – 非阻塞并发队列

**作用**：基于链表的高效并发队列，使用 CAS 算法实现非阻塞，适用于 **高吞吐、数据弱一致性** 的场景。
```java
ConcurrentLinkedQueue<String> queue = new ConcurrentLinkedQueue<>();
queue.offer("item");        // 插入
String item = queue.poll(); // 取出，队列空则返回null
```
### `ConcurrentSkipListMap` / `ConcurrentSkipListSet` – 排序并发容
**作用**：基于 **跳表** 数据结构的 `Map` / `Set`，线程安全且保持元素有序。性能与 `ConcurrentHashMap` 相近，但能保持全局排序。
```java
ConcurrentSkipListMap<Integer, String> map = new ConcurrentSkipListMap<>();
map.put(3, "C");
map.put(1, "A");
map.put(2, "B");
System.out.println(map);    // 输出自动按key排序: {1=A, 2=B, 3=C}
```
# 异步计算
`CompletableFuture` – 异步任务编排神器
**作用**：Java 8 引入，是 `Future` 的增强版。它通过链式调用的方式，编排多个异步任务（串行、并行、聚合），并处理异常。可理解为“**给未来一个承诺，在任务完成时自动执行后续操作**”
- 基础创建：`runAsync` / `supplyAsync`
```java
// 无返回值
CompletableFuture<Void> f1 = CompletableFuture.runAsync(() -> System.out.println("run"));
// 有返回值
CompletableFuture<String> f2 = CompletableFuture.supplyAsync(() -> {
    return "Hello";
});
// 建议：显式传入自定义线程池，避免默认的 ForkJoinPool 公共线程池影响其他任务
```
- 链式串联：`thenApply` / `thenAccept` / `thenRun`
```java
CompletableFuture.supplyAsync(() -> "Hello")
        .thenApply(s -> s + " World")       // 接收前一步结果，返回新结果
        .thenAccept(System.out::println)    // 消费结果，无返回值
        .thenRun(() -> System.out.println("Done")); // 不关心上一步结果，直接执行
```
- 并行组合：`thenCombine` / `allOf` / `anyOf`
```java
CompletableFuture<String> futureA = CompletableFuture.supplyAsync(() -> "Hello");
CompletableFuture<String> futureB = CompletableFuture.supplyAsync(() -> "World");
// 合并两个独立任务的结果
futureA.thenCombine(futureB, (a, b) -> a + " " + b)
        .thenAccept(System.out::println);   // 输出 "Hello World"
// 等待所有任务完成（不聚合结果）
CompletableFuture.allOf(futureA, futureB).join();
// 等待任一任务完成即可继续
CompletableFuture.anyOf(futureA, futureB).join();
```
- 异常兜底：`exceptionally` / `handle`
```java
CompletableFuture.supplyAsync(() -> {
    if (true) throw new RuntimeException("Oops!");
    return "OK";
}).exceptionally(ex -> {
    System.err.println("Error: " + ex.getMessage());
    return "Fallback";               // 返回默认值兜底
}).thenAccept(System.out::println);   // 打印 "Fallback"
```
