# 可变参数
1. 是什么：方法形参列表末尾用“类型... 变量名”声明，调用时可传0~N个同类型实参。
2. 怎么用：调用时直接写值，如 foo(1,2,3)；方法内把该变量当数组用。
3. 原理：编译器把实参自动封装成数组再传入方法。
4. 何时用：当方法需要接受“数量未知但类型相同”的参数时。
注意：
	可变参数只能出现一次且必须放在形参列表末尾，不能与数组形参直接重载冲突，也不能用于泛型类型参数（如 `List<T>...` 会编译警告），并且调用时会隐式创建数组，高性能场景要注意 GC。

# 异常
目的：不是以后不出现异常，而是如果出现异常了如何处理（如：游戏崩溃、卡屏转圈）
## 体系结构：
![[Pasted image 20250811134937.png]]
**Error：代表的系统级别错误（属于严重问题）**  
系统一旦出现问题，Sun公司会把这些错误封装成Error对象。  
Error是给Sun公司自己用的，不是给程序员用的。  
因此我们开发人员不用管它。

**Exception：叫做异常，代表程序可能出现的问题。**  
通常会用Exception及其子类来封装程序出现的问题。
**运行时异常（RuntimeException）：**  
RuntimeException及其子类，编译阶段不会出现异常提醒。  
运行时出现的异常（如：数组索引越界异常）。
**其他异常（编译时异常）：**
编译阶段就会出现异常提醒的。（如：日期解析异常）
## 联系与区别：
![[Pasted image 20250811135500.png]]
编译时异常：因代码本身语法出错，或者做一些性能优化。
			编译阶段出错 java->class文件 过程中。

### 灵魂四问：
![[Pasted image 20250811144151.png]]
1.把try中的代码全部执行完毕，不会执行catch的代码
2.会写多个catch与之对应  
	细节：  
	如果我们要捕获多个异常，这些异常中如果存在父子关系的话，那么父类一定要写在下面
	了解性：  
	在JDK7之后，我们可以在catch中同时捕获多个异常，中间用“|”进行隔开 ，表示如果出现了A异常或者B异常的话，采取同一种处理方案
3.try-catch代码白写，交给JVM处理
4.下面代码不会执行
	直接跳转到对应的catch语句，执行其中语句，若没有对应的，就会交给JVM处理。

# File
File对象就表示一个路径，可以是文件的路径，也可以是文件夹的路径。 
这个路径可以是存在的，也可以是不存在的。
不知道当前[[JDBC#配置路径]]可看。
常见方法：
![[Pasted image 20250811170704.png]]
先给它转为对象，再进行操作。
#### 路径：
- **绝对路径**：从根开始写的完整路径，**不依赖当前位置**（从根目录开始）
- **相对路径**：以当前目录为基准的“短”路径，**依赖当前位置**（从当前目录所在目录开始）
