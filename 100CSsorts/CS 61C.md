- **定义**：段错误是指程序试图访问一个未被允许访问的内存区域，或者试图以错误的方式访问允许访问的内存（例如向只读内存写入数据）。操作系统检测到这类非法访问后，会向进程发送 **SIGSEGV** 信号，导致程序异常终止。

- **定义**：总线错误通常表示硬件层面的内存访问问题，即CPU检测到无法正常进行的内存操作。它会触发 **SIGBUS** 信号，导致程序终止。

- 与栈不同，内存只有在程序员**显式**清理时才会被重用

- **静态数据 (Static Data)**：在 main 函数外部声明的变量，不会增长或收缩

代码段是存放所有指令的地方，程序中每条代码都有对应的地址。
释放两次同一块内存（即双重释放，double free）会导致**未定义行为**。具体后果可能包括：
- **堆内存损坏**：内存分配器内部的数据结构被破坏，可能导致后续的 `malloc` 或 `free` 操作失败、程序崩溃，或在完全无关的代码位置引发难以调试的错误。
- **use-after-free 风险**：在第一次释放后，那块内存可能被重新分配给其他指针。第二次释放时，实际上释放的是其他对象的内存，造成数据混乱或安全漏洞。
- **程序崩溃**：许多内存分配器在检测到双重释放时会直接终止程序（例如触发 abort），以防止更严重的破坏。
- **安全漏洞**：攻击者可能利用双重释放实现任意内存写入，进而劫持控制流（例如通过“malloc 欺骗”技术）。

# lec08-RISC-V `DataTransfer`

存储程序概念：程序可以存储在内存中。
数据传输：从内存中加载以及存储。（也是对内存所做的唯一操作）

数据大小通常和芯片大小有关，如32位或者64位。
访问内存时是通过字节（8bit）来寻址的，这也被称为字节寻址内存。
word（字地址）= 4 byte（字节）
字地址要和最右边的字节地址相同，即最低有效字节地址。

| 术语             | 大小          | 说明                      |
| -------------- | ----------- | ----------------------- |
| **Byte**       | 8 bits      | 最小单位                    |
| **Halfword**   | 16 bits     | 2 bytes                 |
| **Word**       | **32 bits** | **4 bytes** ← RISC-V 默认 |
| **Doubleword** | 64 bits     | 8 bytes                 |

>在 **32位 RISC-V（RV32）** 中，**1 word = 32 bits = 4 bytes**
>在 **64位 RISC-V（RV64）** 中，**1 word = 32 bits**（仍然），但常用 doubleword（64位）**而 64 位称为 doubleword**（双字）。这是为了保持与 32 位指令和数据格式的兼容性。

**word 是 CPU 一次能够自然处理的数据大小**，通常与通用寄存器的位宽一致。

本节重点是：如何在CPU和内存之间来回传输数据？
代码要么经过编译器自动完成，要么是手动编译，
	编译过程将C代码转换为RISC-V指令集
你所使用的寄存器总数称为 **”足迹“**。（减少足迹使用，或者巧妙重复使用哪些已经被”擦除“的足迹）
```
加载寄存器，偏移量，基地址
存储寄存器，偏移量，基地址
```

$例如，lb x10, 3(x11)$
- **指令格式**：字节传输指令的格式与字传输指令`lw`/`sw`相同，使用基址寄存器加偏移量的寻址方式。
- **功能示例**：`lb x10, 3(x11)` 的含义是：
    1. 计算内存地址：将立即数`3`与寄存器`x11`的内容相加得到有效地址。
    2. 从该地址读取一个字节（8位）的数据。
    3. 将该字节写入目标寄存器`x10`的**最低8位**。
    4. 寄存器的高24位如何处理？图中用“xzzz zzzz”示意，实际在RISC-V中，`lb`指令会进行**符号扩展**：将加载的字节视为有符号数，把它的最高位复制到高24位，以保持数值不变。如果是无符号加载（`lbu`），则高24位补零。
![[Pasted image 20260222232728.png]]
- 图中画出了一个 32 位寄存器 `x10`，其高位部分用 `XXXX` 表示尚未确定的位，低位是一个已加载的字节（“byte loaded”）。
- 关键点在于“This bit”指向加载的字节的最高位（即符号位），这个位会被复制到寄存器的高 24 位中（图中箭头所示），这个过程就是**符号扩展**。

![[Pasted image 20260222234653.png]]
```
1. **`addi x11, x0, 0x93F5`**
    
    - 将立即数 `0x93F5` 存入寄存器 `x11`，在32位RISC-V中，该数表示为 `0x000093F5`（高16位为0）。
        
2. **`sw x11, 0(x5)`**
    
    - 将 `x11` 的值存储到以 `x5` 为基址的内存中，采用小端序：  
        地址 `x5+0`：`0xF5`（最低字节）  
        地址 `x5+1`：`0x93`  
        地址 `x5+2`：`0x00`  
        地址 `x5+3`：`0x00`
        
3. **`lb x12, 1(x5)`**
    
    - 从地址 `x5+1` 加载一个字节，即 `0x93`。
        
    - `lb` 指令进行符号扩展：`0x93` 的最高位为1，因此高24位全部补1，得到 `0xFFFFFF93`。
```
为什么2只加到3？
	因为 `sw` 指令存储的是一个 **字（word）**，在RISC-V中一个字为 **4字节**，所以它占用了从基址 `x5` 开始的连续4个内存单元：偏移量为 `0`、`1`、`2`、`3`。因此地址只加到3，之后的下一个地址（偏移4）属于下一个字。
**x0 有什么含义？**
	1. `x0` 是RISC-V架构中的**零寄存器**，其值恒为 `0`。任何对 `x0` 的写入都被忽略，读取时总是返回 `0`。  
	2. 在指令 `addi x11, x0, 0x93F5` 中，用 `x0` 作为源寄存器相当于将立即数 `0x93F5` 直接加载到 `x11` 中，因为 `x0 + 0x93F5 = 0x93F5`。这是一种常见的初始化寄存器的方式。

| `bgeu` | branch if greater or equal **unsigned** | 大于等于则跳转      | **无符号** |
| `j`    | jump                                    | 无条件跳转到 label |         |
**无条件分支** —— 不依赖任何条件，**总是跳转**（**只有 j 一个**）
**关键点**：
1. **比较两个寄存器** —— 例如 `beq x1, x2, label`（如果 x1 == x2，跳转到 label）
2. **有符号 vs 无符号** —— 带 `u` 后缀的是无符号比较（用于地址、位模式等）
3. **没有单独的 `bgt` 或 `ble`** —— 通过交换操作数用 `blt`/`bge` 实现
4. `j label` 是 **伪指令（pseudo-instruction）**
- 实际汇编器会把它转换为：`jal x0, label`
    - `jal` = Jump and Link（跳转并保存返回地址）
    - `x0` 是零寄存器，表示**不保存返回地址**（纯跳转，不返回）

# lec10-RISC-V Procedures
调用函数的六个步骤：
1. **将参数（arguments）放到函数能够访问的位置**
2. **将控制权转移给函数**
3. **获取函数所需的（局部）存储资源**
4. **执行函数的预期任务**
5. **将返回值（return value）放到调用代码能够访问的位置；恢复使用过的寄存器；释放局部存储**
6. **将控制权返回到调用点，因为函数可以从程序中的多个位置被调用**
在 RISC-V 中，函数调用是通过寄存器来传递参数、返回值和返回地址的，而不是通过内存（栈），因为寄存器比内存快得多。
基本思想：**寄存器比内存快得多**。

函数调用时使用的寄存器和基本原则：
- **a0 到 a7** 是 8 个参数寄存器，用来传递函数调用的前 8 个参数。
- **a0 和 a1** 也用来存放返回值（比如返回一个 64 位整数或两个 32 位整数）。
- 如果参数超过 8 个，或者太大放不进寄存器，才会用栈内存。
- **`ra（return address）`** 是存放函数返回地址的寄存器，也就是函数调用完后要跳回的地方。在调用函数（比如 `jal` 指令）时，CPU 会自动把下一条指令的地址存到 `ra` 里。
- 如果函数调用**被调用者保存的寄存器**，它得先保存原来的值（通常压栈），用完再恢复。

栈会从高地址向低地址方向增长。
**栈帧包含**：（这三个关键信息一个对应一个word，也就是4字节）
- **返回"指令"地址** —— 函数执行完后要回到哪里继续执行
- **参数（arguments）** —— 传递给函数的参数
- **其他局部变量的空间** —— 函数内部定义的局部变量存储区域
**栈帧是连续的内存块**
- 栈帧是**连续的内存块**
- **栈指针（stack pointer）** 指示栈帧的底部位置（`$sp` 寄存器）
**过程结束时**
- 当过程（函数）结束时，**栈帧被从栈中丢弃**
- **释放内存**，供未来的栈帧使用
![[Pasted image 20260226233734.png]]

---
**RISC-V 函数调用约定（Calling Convention）**
- **Caller（调用者）**：发起调用的函数
- **Callee（被调用者）**：被调用的函数
- 当被调用者执行完毕返回时，**调用者需要知道哪些寄存器可能被修改了，哪些寄存器保证不变**
- **寄存器约定（Register Conventions）**：一套普遍接受的规则，规定在过程调用（`jal`）之后，**哪些寄存器保持不变，哪些可能被修改**

寄存器分类

为了减少昂贵的内存加载/存储操作（避免频繁保存/恢复寄存器），RISC-V 函数调用约定将寄存器分为两类：
1. 函数调用期间**保持不变**（Preserved）
- 调用者可以依赖这些值不被改变
- 包括：`sp`（栈指针）、`gp`（全局指针）、`tp`（线程指针）
- **"保存寄存器" s0 - s11**（s0 也是 fp，帧指针）
> **被调用者责任**：如果用到了这些寄存器，必须先保存，返回前恢复

1. 函数调用期间**不保证不变**（Not Preserved）
- 调用者**不能**依赖这些值保持不变
- 包括：**参数/返回值寄存器 a0 - a7**、`ra`（返回地址）
- **"临时寄存器" t0 - t6**
> **调用者责任**：如果需要保留这些值，自己提前保存
# lec11-RISC-V Instruction Format 1
指针认证码，检查你是否在访问无效内存或不属于你的内存，硬件会进行几次双重检查。
**程序计数器（PC）**：PC寄存器专门用于存放下一条将要执行指令的地址，它本身就是一个指向内存的指针。在Intel x86架构中，它被称为指令指针（IP）。
许多指令集架构实际上是**向后兼容**的。
- 任何事情（指令，数据，字）都有其对应存储地址。
- 程序以二进制形式分发，也就是汇编后的机器码。
每个field（字段）是那32位中的一个位集。

1. **指令的字段划分**：每条 32 位的 RISC-V 指令被划分为多个字段，每个字段携带特定的信息（如操作码、寄存器编号、立即数等），处理器根据这些字段解码并执行操作。
2. **六种基本指令格式**：RISC-V 通过有限的几种格式来支持所有指令，以保持硬件设计的简洁和规整。这六种格式分别是：
    - **R 格式**：用于寄存器-寄存器之间的算术运算（如 add, sub）。
    - **I 格式**：用于寄存器与立即数之间的算术运算（如 addi）以及加载指令（如 `lw`）。
    - **S 格式**：用于存储指令（如 `sw`）。
    - **B 格式**：用于条件分支指令（如 `beq`），是 S 格式的微小变体。
    - **U 格式**：用于 20 位高位立即数指令（如 `lui, auipc`）。
    - **J 格式**：用于无条件跳转指令（如 `jal`），是 U 格式的微小变体。
3. **设计理念**：RISC-V 追求简单和规整，尽量让同类指令共享相同的格式，从而简化译码逻辑，降低硬件复杂度。

## R 型指令格式:
![[Pasted image 20260227192959.png]]
- **opcode**（7 位）：操作码，标识指令的大类（如整数运算、分支等）。
- **`rd`**（5 位）：目标寄存器编号，用于存放运算结果。
- **funct3**（3 位）：与 opcode 共同指定指令类型（如加法、减法、逻辑运算等）。
- **rs1**（5 位）：第一个源操作数寄存器编号。
- **rs2**（5 位）：第二个源操作数寄存器编号。
- **func7**（7 位）：与 funct3 和 opcode 配合，精确区分具体操作（如加法 `0000000` 与减法 `0100000`）。

 1. 立即数指令

2. 加载指令

```plain
lb: "load byte," lh: "load halfword" (16 bits)
```
两者的作用都是进行符号拓展。
- **lb**（加载字节）和 **lh**（加载半字）将内存中的8位或16位数据**符号扩展**为32位后存入目标寄存器。
- **lbu**（加载无符号字节）和 **lhu**（加载无符号半字）则进行**零扩展**。
- **没有 `lwu` 指令**，因为加载32位字（lw）时，数据已占满整个寄存器，无需扩展，这也体现了 RISC-V 追求简洁的设计理念。
**零扩展**（Zero Extension）是一种数据填充方式，用于将较短的数据（如8位或16位）扩展为较长的数据（如32位）时，**高位直接补0**。

` PC（Program counter）`：

PC相对寻址：
- 指令中提供一个**有符号偏移量**（以字节为单位），更新 PC 的方式为：`PC = PC + 偏移量`。
- 这种方式的优点是：如果整个代码段在内存中移动（例如动态链接、地址空间布局随机化），相对偏移量保持不变，从而生成**位置无关代码**。
绝对寻址：
- 绝对寻址直接给出新地址覆盖 PC：`PC = new_address`。
- 缺点：代码移动后需要修改地址（缺乏灵活性），且构造 32 位立即数需要多条指令，效率较低。因此只在必要时使用。

**B 格式的字段划分**
B 格式是专门为条件分支设计的，其 32 位分配如下：
- **opcode**（7 位）+ **funct3**（3 位）+ **rs1**（5 位）+ **rs2**（5 位）= 20 位固定字段。
- 剩余 **12 位**用于存储 PC 相对寻址的**有符号立即数**（即偏移量）。
    - 由于是**有符号补码**表示，可表示的偏移范围是 **±2¹¹ 个“单位”**。
    - 这里的“单位”通常指**字节**，但由于指令按 2 字节（压缩指令）或 4 字节对齐，实际偏移量会经过缩放（通常乘以 2），因此可跳转范围更大。

---
**RISC-V 分支指令中偏移量单位为何固定为 2 字节**？
RISC-V 基础指令集（RV32、RV64、RV128）的指令字长都是 **32 位**，但它支持扩展：
- **16 位压缩指令**（C 扩展）
- **可变长度指令**（以 16 位为倍数）
为了兼容这些扩展，**即使系统当前只使用 32 位指令**，分支偏移量的单位也固定为 **2 字节**（而不是 4 字节），以确保未来加入 16 位指令时，硬件不需要修改。
- 12 位有符号立即数原本可表示 ±2¹¹ 个“单位”。
- 单位是 2 字节，所以最大字节偏移为 ±2¹¹ × 2 = ±4096 字节。
- 但由于每条指令占 4 字节，因此实际能跳转的**32 位指令条数**为：
![[Pasted image 20260228173229.png]]
- 也就是说，虽然 12 位立即数有 2048 个编码值，但因为单位是 2 字节，而指令是 4 字节对齐，**有效目标只有一半**（偶数索引的 2 字节单位才对应指令开头）。
**条件分支指令只能跳转到当前 PC 前后最多约 1024 条指令的位置**（即 ±2¹⁰ 条指令）。

**RISC-V 指令格式中立即数字段的布局**

- **寄存器字段位置固定**：在所有指令格式中，`rs1`、`rs2`、`rd` 等字段始终位于相同的位范围，简化了寄存器读取逻辑。
- **立即数位位置也尽量保持一致**：即使在不同格式间，立即数的各个位也尽可能放在相同的位置，减少解码电路的复杂度。
## J 型指令格式:
**格式**：`jal rd, Label`
1. **跳转**：将程序计数器（PC）设置为标签 `Label` 处的地址（采用 PC 相对寻址）。
2. **链接**：将**下一条指令的地址**（即 `PC+4`）写入目标寄存器 `rd`。
这一机制为函数调用提供了基础——保存了返回地址。
- `j` 是伪指令，实际对应 `jal x0, Label`。
- `jal` 同时完成“跳转”和“保存返回地址”两个动作，是函数调用的核心指令。
- 通过选择不同的目标寄存器（`ra` 用于调用，`x0` 用于无条件跳转），一条硬件指令即可覆盖两种常见需求。

两种主要使用场景：
（1）函数调用（需要返回）
- 使用 `jal` 指令，并将返回地址存入**链接寄存器**（通常为 `ra`，即 `x1`）。
- 例如：`jal ra, function`  
    跳转到 `function` 执行，同时将返回地址保存到 `ra`，函数执行完毕后可通过 `jr ra` 返回。
（2）无条件跳转（不需要返回）
- 通过将目标寄存器设为 `x0`（零寄存器），实现“跳转但不保存返回地址”。
- RISC-V 提供了 **`j` 伪指令**，它被汇编器翻译为 `jal x0, Label`（因为写入 `x0` 无效，等价于仅跳转）。
- 这种用法相当于其他架构中的无条件跳转指令（如 `jmp`）。

J指令的形式，目的在于允许更长的跳转，更长的无条件跳转。

## U 型指令格式:
当需要更多的位存储信息时需要用到这个指令。

需要rd指向更新高位部分的寄存器。

---
格式：`lui rd, imm`
- 将20位立即数 `imm` 左移12位，写入目标寄存器 `rd` 的高20位，同时将低12位清零。
- 即：`rd = imm << 12`
**构造任意32位立即数**
- 单独使用 `lui` 只能设置高20位，低12位为0。
- 配合 `addi` 指令可填充低12位，从而生成任意32位数值。
```
lui x10, 0x87654      # x10 = 0x87654000
addi x10, x10, 0x321  # x10 = 0x87654321
```
**`li` 伪指令**
- RISC-V 汇编提供了 `li`（Load Immediate）伪指令，用于直接加载32位立即数。
- 汇编器会根据立即数大小自动将其转换为合适的 `lui` + `addi`（或其它指令）组合，简化编程。


由于 `addi` 指令会对 12 位立即数进行**符号扩展**而可能引发的错误，以及相应的解决方法。
![[Pasted image 20260228182625.png]]
核心问题:
- 想要将寄存器 `x10` 设为 `0xBOBACAFE`。
- 尝试：  
    `lui x10, 0xBOBAC` → 得到 `0xBOBAC000`  
    `addi x10, x10, 0xAFE` → 由于 `0xAFE` 的 12 位二进制最高位为 1（即它是一个负数），`addi` 会将其符号扩展为 `0xFFFFFAFE`，实际执行的是 `x10 = 0xBOBAC000 + 0xFFFFFAFE = 0xBOBABAFE`，结果错误。

原因
- `addi` 对 12 位立即数进行**符号扩展**，若最高位为 1，则高位补 1，相当于减去一个值（因为补码表示负数）。
- 这导致实际加上的值与预期不符，使得最终结果的高 20 位比目标值小 1。
解决方法
- 如果低 12 位立即数是负数（即其值 ≥ 0x800），则需在 `lui` 的高 20 位中预先**加 1** 以抵消减法的影响。
- 正确做法：  
    `lui x10, 0xBOBAD` → 得到 `0xBOBAD000`  
    `addi x10, x10, 0xAFE` → 实际加上 `0xFFFFFAFE`，得到 `0xBOBAD000 - 0x502 = 0xBOBACAFE`，结果正确。

![[Pasted image 20260228182950.png]]
**格式**：`auipc rd, imm`
**操作**：将 20 位立即数 `imm` 左移 12 位后，与当前 PC 值相加，结果写入目标寄存器 `rd`。
![[Pasted image 20260228183048.png]]
- 与 `lui` 不同，**`lui` 与 PC 无关，而 `auipc` 是基于 PC 的**，因此可以生成相对于当前指令位置的地址。
示例
- `auipc x5, 0xABCDE`  
    执行后 `x5 = PC + 0xABCDE000`（因为左移 12 位，低 12 位补 0）。

实际应用
- **获取当前指令地址**：`auipc x5, 0`  
    由于立即数为 0，这条指令实际上将当前 PC 值直接加载到 `x5` 中，相当于“读取 PC 到寄存器”。
- 常用于实现**位置无关代码**，例如：
    - 计算全局变量或常量的地址（与 PC 的相对位置）。
    - 与 `jalr` 配合实现远距离跳转。
    - 在动态链接或共享库中获取运行时地址。

## `jalr` -I 型指令格式:
![[Pasted image 20260228183545.png]]
格式：`jalr rd, rs1, imm`
- 先计算目标地址：`PC = rs1 + imm`（将基址寄存器 `rs1` 的值与有符号立即数 `imm` 相加，得到跳转目标）。
- 同时将**下一条指令的地址**（即 `PC+4`）写入目标寄存器 `rd`，用于保存返回地址。
**使用场景：函数返回**
- 当需要从函数返回时，通常使用 `jr ra` 伪指令，它被汇编为 `jalr x0, ra, 0`。
    - 因为目标寄存器是 `x0`，所以不会保存返回地址，仅实现跳转：`PC = ra + 0`，即跳转到 `ra` 指向的地址（调用者的返回地址）。
- 这一用法简洁地实现了子程序返回。
