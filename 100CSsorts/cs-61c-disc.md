# 03-Floating Point
内存：
- Stack：函数内部使用的临时存储区，可以修改局部变量数据（局部变量、局部常量、函数参数）
- Heap：以malloc、calloc、realloc闻名，这些函数由用户确定是否使用，用于动态分配、移动或调整内存大小
- Static：不可变的内存区域，程序终止时由机器清理。（全局变量、静态变量、#define 定义的常量、字符串常量如 `char *s = "text"`）
- Code(代码段)：可执行的/已编译的 C 代码块

两种不同的声明方式：
- **char s[] = "hello"**
    - 是一个**数组结构**，支持索引访问
    - **可以修改**（字符串存储在**栈**上）
- `char *p = "hello"`
    - 是一个**指针变量**，初始化为地址值，但可以用 `++` 操作
    - 也支持索引访问
    - **不能修改**（字符串存储在**静态区**，修改会导致段错误 `segfault`）
    - 如需修改或复制静态字符串，使用 `strcpy()`
**两种情况中，指针本身都存储在栈上**
通常不会返回一个字符数组:
	因为**函数返回时，栈上的局部数组会被销毁**，导致返回的指针成为**悬空指针（Dangling Pointer）**，指向已释放的无效内存。

动态分配：
- **内存分配在堆上**
- **必须在从 main 函数返回前释放内存，否则会导致内存泄漏！**
    - `Malloc`：内存分配
        - 如果没有可用内存则返回 void
    - `Calloc(nitems, size)`：分配一块已清零的内存
    - `Realloc(void *ptr, size_t newSize)`：重新分配内存
        - 为相同数据重新分配不同大小的内存，在调整大小时如有必要会自动为你释放原内存
- **内存分配在堆上，所有控制权都交给程序员！**

| 函数                       | 用途       | 特点                  |
| ------------------------ | -------- | ------------------- |
| `malloc(size)`           | 分配内存     | 不初始化，返回 `NULL` 表示失败 |
| `calloc(n, size)`        | 分配数组内存   | 自动初始化为 0            |
| `realloc(ptr, new_size)` | 重新调整内存大小 | 自动处理数据迁移和旧内存释放      |

---
RISC-V（精简指令集计算机）
RISC-V 是一个由 CPU 和主存组成的系统。它使用由简单指令组成的汇编语言来执行单个任务。
- CPU 负责计算，速度极快（约每条指令 1 纳秒）。
- 主存用于长期存储数据，速度比 CPU 慢得多。
- CPU 可以通过寄存器存储数据。
    - 寄存器是 CPU 中存储二进制数据的硬件组件（类似于物理变量）。
RISC-V 中有 32 个寄存器
- 在本课程中，我们只考虑 32 位系统：寄存器宽度为 32 位（1 字 = 32 位）。
- 寄存器编号为 0 到 31（x0 到 x31）。
- 寄存器没有类型。
- 寄存器 x0 是特殊的，固定存储 0。
- 寄存器**不是变量！**
---
**RISC-V 汇编语言的基本语法和寄存器约定**
1. 指令格式
- 通用格式：`<指令名称> <目标寄存器> <操作数>`
- 逗号是可选的（例如 `add x1, x2, x3` 或 `add x1 x2 x3` 均可）。

2. 寄存器的分类与用途
RISC-V 有 32 个寄存器（`x0`–`x31`），根据调用约定赋予不同名称和用途：

|寄存器|名称|用途说明|
|---|---|---|
|`x0`|`zero`|硬连线为 0，始终读回 0|
|`x1`|`ra`|返回地址（Return Address）|
|`x2`|`sp`|栈指针（Stack Pointer）|
|`x3`|`gp`|全局指针（Global Pointer）|
|`x4`|`tp`|线程指针（Thread Pointer）|
|`x5`–`x7`|`t0`–`t2`|临时寄存器（caller-saved）|
|`x8`|`s0` / `fp`|保存寄存器 / 帧指针|
|`x9`|`s1`|保存寄存器|
|`x10`–`x11`|`a0`–`a1`|函数参数/返回值|
|`x12`–`x17`|`a2`–`a7`|函数参数|
|`x18`–`x27`|`s2`–`s11`|保存寄存器（callee-saved）|
|`x28`–`x31`|`t3`–`t6`|临时寄存器（caller-saved）|
3. 关键提示
- 寄存器 **不是变量**，它们是 CPU 内部的物理存储单元。
- `x0` 是特殊的，始终为 0，常用于清零或占位。
- 名称（如 `t0`、`s1`、`a0`）遵循 RISC-V 应用程序二进制接口（ABI）规范，便于程序员理解寄存器用途。
```ABI命名约定
- **s0–s11（保存寄存器）**  
    这些寄存器中的值在函数调用过程中**必须被保存**。如果一个函数要使用它们，需要先将其原值压栈保存，返回前恢复，以保证调用者（caller）看到的值不变。
    
- **t0–t6（临时寄存器）**  
    这些寄存器中的值在函数调用过程中**不必保存**。如果调用者需要其中的数据在调用后依然有效，就必须自己保存（例如压栈）。因此它们适合存放临时计算结果。
    
- **a0–a7（参数寄存器）**  
    用于传递函数参数和返回值。其中 `a0` 和 `a1` 也用于返回值。调用函数时，参数依次放入这些寄存器；返回时，返回值也放在 `a0`（和 `a1`）。
    
- **ra（返回地址寄存器）**  
    存放函数调用后要返回到的地址。当使用 `jal` 或 `jalr` 指令调用函数时，返回地址自动存入 `ra`。
    
- **sp（栈指针）**  
    始终指向当前栈顶，用于函数调用时的栈帧管理（如分配局部变量、保存寄存器等）。
```
---
**基本运算指令**
1. 整数加减法
- **指令格式**：`add rd, rs1, rs2` 和 `sub rd, rs1, rs2`
- **作用**：将两个源寄存器（`rs1`、`rs2`）的值相加/相减，结果存入目标寄存器（`rd`）。
2. 移位操作
移位指令将寄存器中的二进制位整体向左或向右移动，空出的位用特定值填充。
	逻辑移位
- **左移 (`sll`)**：低位补0，相当于**无符号数乘以2ⁿ**。
- **右移 (`srl`)**：高位补0，相当于**无符号数除以2ⁿ**。
- **用途**：处理**无符号数**的快速乘除。
	算术移位
- **左移 (`sla`)**：与逻辑左移相同（低位补0），同样用于乘法。
- **右移 (`sra`)**：高位**复制原来的符号位**（即符号扩展），保持负数除以2ⁿ后仍为负数。
- **用途**：处理**有符号数**的除法（右移），左移与逻辑左移相同。
---
控制：
**Branch（分支）**—— 类似于 if 语句的使用方式。可以根据寄存器的内容，从当前代码行跳转到指定的 `label`（标签）。
**Jump And Link（跳转并链接）**—— 无条件跳转。将 `rd`（目标寄存器）设置为 PC+4，然后跳转到指定的 `label`。
```plain
PC+4 = 当前指令的下一条指令地址 = 函数执行完后应该回到的地方
```
**Pseudoinstructions（伪指令）**存在于不需要保存返回地址的情况下：
- `"j label"` 和 `"jr x1"`
**Links（链接）**用于追踪跳转发生前 PC（程序计数器）所在的代码行
- 可以将其理解为**函数调用**

| **带返回的跳转** | `jal`（即 `jal ra`）   | `jalr`（即 `jalr ra`）   |

- 对代码进行两遍扫描（遍历）

	代码块（需要通过标签跳转执行的显式操作）
一次遍历处理所有向前引用，以及所有标签的定义，同时静态数据也会被存储到符号表中；
在第二次遍历中尽可能地解析重定向表。

- 符号表：标签和静态数据引用的列表
- 重定位表：需要由链接器解析的标签或数据引用
- 调试信息
包含两个表： 符号表 和 重定向表。

**RISC-V 调用约定（Calling Convention）**
函数调用时，寄存器和栈的使用规则：规定了哪些寄存器由被调用者（callee）保存，哪些由调用者（caller）保存，以及函数开头和结尾需要做的操作。
- **被调用者保存的寄存器（Preserved registers）**：`s` 寄存器和 `ra` 寄存器  
    这些寄存器的值在函数调用前后必须保持不变。如果被调用函数要用到它们，必须先在栈上保存原值，返回前恢复。
- **调用者保存的寄存器（Non-preserved registers）**：`a` 寄存器和 `t` 寄存器  
    调用者（caller）在调用函数前，如果这些寄存器中有重要数据，需要自己保存到栈上；被调用者可以随意修改它们，不需要恢复。

被调用者（Callee）
每个函数在开头和结尾需要执行固定的代码块，称为 **序言（Prologue）** 和 **尾声（Epilogue）**。
- **序言（Prologue）**：  
    在函数入口处，将需要用到的被调用者保存寄存器（如 `ra` 和某些 `s` 寄存器）压入栈中。因为 `ra` 保存了返回地址，如果该函数内部还会调用其他函数，原来的 `ra` 会被覆盖，所以必须先保存。
- **尾声（Epilogue）**：  
    在函数返回前，从栈中弹出之前保存的寄存器值，恢复到相应寄存器，然后执行返回指令（`ret`，实际是 `jalr x0, ra, 0`）。

调用者（Caller）
如果调用者当前在某些 `t` 寄存器中存有重要数据，并且不希望被接下来的函数调用破坏，就需要在调用前将这些 `t` 寄存器保存到栈上，调用结束后再从栈中恢复。因为被调用者可以随意修改 `t` 寄存器，不会负责恢复
```example
假设函数 A 调用函数 B：

- 函数 A（调用者）：
    - 如果它把重要数据放在 `t0` 中，担心 B 会修改，就先把 `t0` 压栈。  
    - 然后调用 B。  
    - B 返回后，从栈中弹出 `t0` 恢复原值。
 
- 函数 B（被调用者）：
    - 如果它要用到 `s1` 和 `ra`，就在序言中把它们压栈。
    - 函数体执行过程中可以随意使用 `s1`（因为已经保存了原值）和 `t`、`a` 寄存器。 
    - 返回前，从栈中恢复 `s1` 和 `ra`，然后 `ret`。
```

**Synchronous Digital System**（同步数字系统）   **重点**
SDS术语：
- 时钟（clk）：整个 SDS 的中央定时单元；通常每个系统只有一个时钟
    - 注意：这并不意味着所有定时单元都会跟随同一个信号
- 状态元件：任何有时钟控制的元件；具有持久性（即存储值）
	可以保存一个值，依赖时钟来更新该值
- 逻辑元件：任何无时钟控制的元件；无持久性；组合逻辑元件
	与或非门，不依赖时钟，可直接接收输入并输出结果
- 触发器（FF）：存储 1 位值（0/1）的状态元件
	寄存器包含FF
- 寄存器：n 位状态元件；由 n 个级联的触发器构成
这些会成为电路的主要组件。

时钟上升沿（RCE）：时钟从 0 变为 1 的时间段（假设为瞬时）（粉色）
	状态元件依赖时钟的上升沿来处理输入并输出结果
时钟下降沿（FCE）：与上升沿类似，但时钟从 1 变为 0（紫色）
建立时间：在时钟上升沿之前，输入（信号）必须保持稳定的时间长度（点划线）
	在时钟边沿之前（竖实线之前虚线之后），输入信号能够稳定一段时间
保持时间：与建立时间类似，但在时钟上升沿之后（点线）
	在时钟边沿之后（虚线之前竖实线之后），希望保持一段时间以便处理该值（存入内存/持久化/发送出去）
时钟到 Q 时间（c2q）：时钟上升沿之后，输入（D）在输出（Q）上实现/可访问所需的时间长度；c2q ≥ 保持时间（虚线）

**同步数字系统（SDS）中的时序约束方程**
目的是确保电路中的触发器能正确捕获数据，避免因信号传播延迟不当导致的错误。
1.**最大保持时间约束**
![[Pasted image 20260302230524.png]]

# 07-Single-Cycle Datapath
CPU 执行一条指令时，从左到右经历5个阶段（由蓝线分割）：
	IF、ID、EX、MEM、WB
![[Pasted image 20260303110051.png]]
控制逻辑-转存：
- **`PCSel`**: 下一条指令的位置——来自ALU的计算结果 或 PC+4
- **`Inst[31:0]`**: 将当前指令发送给控制单元
- **`ImmSel`**: 根据指令类型格式化立即数    
- **`RegWEn`**: 使能写入寄存器堆
控制逻辑-分支：
- **`BrUn`**：分支指令的控制信号，指示将数值视为**有符号数**还是**无符号数**进行比较
- **`BrEq`**：(数据 A == 数据 B)? 1 : 0 （输入信号）
	表示两个数据是否相等。
- **`BrLt`**：(数据 A < 数据 B)? 1 : 0 （输入信号）
	表示数据 A 是否小于数据 B。
控制逻辑-选择器：
- **`BSel`**：选择**立即数**还是**rs2**作为ALU的输入。
- **`ASel`**：选择**PC**还是**rs1**作为ALU的输入。
- **`ALUSel`**：选择要执行什么操作（4位控制信号,意味着可支持的操作数量-16）。    
- **`MemRW`**：对内存进行**读**或**写**。

---
步骤1: **指令获取阶段（`Instruction Fetch，IF`）**
1. **从内存中取出指令**：
    - CPU 会查看**程序计数器（PC，Program Counter）**中存储的地址。
    - 根据这个地址，去指令内存（Instruction Memory）中找到对应的指令。
    - 将这条指令的机器码（也就是 0 和 1 组成的二进制代码）读取出来。
2. **更新程序计数器**：
    - 因为当前这条指令正在被处理，CPU 需要为读取下一条指令做准备。
    - 由于这里提到的是 32 位指令（通常占用 4 个字节的内存空间），所以会将 PC 的值**增加 4**，让 PC 指向内存中的下一条指令。

步骤2: **指令解码阶段（`Instruction Decode，ID`）**
**解析指令**：
- 查看指令中的**操作码**和其他相关字段，判断这是哪一类指令（比如是加法、减法，还是从内存读数据）。
**准备操作数**：
- 根据指令格式，找出这条指令需要用到哪些寄存器。
- 从寄存器堆中读取这些寄存器的当前值，为后续的执行阶段做准备。
**处理立即数**：
- 如果指令中包含立即数，则对其进行**符号扩展**处理，把它变成 CPU 能够直接使用的标准长度。

步骤3: **执行阶段(`Execute,EX`)**
**执行算术逻辑运算**：
- 所有的算术和逻辑操作都由 **ALU（算术逻辑单元）** 来完成。
- 比如加法、减法、按位与、按位或等指令，在这个阶段计算出最终结果。
**计算内存地址**：
- 如果是加载（Load）或存储（Store）指令，需要访问内存中的数据。此时 ALU 会计算出数据在内存中的具体地址（通常是“基地址 + 偏移量”）。
**处理分支跳转**：
- 如果当前指令是分支指令（比如条件跳转），CPU 会在这里判断条件是否成立，决定下一条指令是**继续顺序执行**，还是**跳转到别的地址**。

步骤4: **内存访问阶段**（Memory ，MEM）
**只服务于访存指令**：
- 只有**加载（lw）** 和 **存储（sw）** 指令会在这个阶段用到。
- 其他指令（如加法、逻辑运算）在此阶段不进行任何操作，直接传递到下一级。
**具体操作**：
- **读内存**：如果是 `lw`（加载字）指令，根据上一步执行阶段计算出的地址，从数据内存中读取数据。
- **写内存**：如果是 `sw`（存储字）指令，将寄存器中的值写入到执行阶段计算出的内存地址中。
**关于缓存**：
- 现代处理器中，这个阶段访问的通常是**高速缓存（Cache）**，而不是慢速的主内存。
	如果数据在缓存中命中，读写速度会极快；如果未命中，则需要花费更多周期到主存中查找。

步骤5: **写回阶段**
**确定写回的数据**：
- 决定要把什么值写回到寄存器里。这个值可能来自上一步内存阶段读取到的数据（对于 `lw` 指令），也可能来自执行阶段 ALU 计算出的结果（对于普通运算指令）。
**条件性写入**：
- **只有需要写回寄存器的指令才会在这个阶段生效**。
- 比如 `add`（加法）或 `lw`（加载）指令，它们需要把计算结果或读到的数据存到寄存器里，就会执行写回操作。
- 而像 `sw`（存储）或 `beq`（分支跳转）这类指令，不需要修改寄存器，所以在这个阶段什么都不做。
# 08-Pipelining、Hazards
流水线数据路径：
	在数据路径中加入了额外的寄存器，以期缩短关键路径。
**提高效率的原理**：
- 在单周期设计中，每个指令处理过程中，总有一部分硬件是闲置的。
- 流水线技术让这些“闲置”的部件也工作起来——当一条指令在执行时，下一条指令已经开始取指，实现硬件资源的充分利用。
**理想效率目标**：
- 对于一个 n 级的流水线，理论上最高效率是同时有 n 条指令在流水线中重叠执行。
- 例如五级流水线，理想状态下是五条指令同时处于不同阶段。

## **流水线冒险**
- **根源**：所有冒险都是由某种**依赖关系**引起的。
- **后果**：冒险会阻止后续指令**正确执行**（如果它们贸然开始的话），或者阻止它们在**下一个时钟周期按时开始**。

流水线可能遇到的麻烦分成三类:

---
1.**结构冒险**
- **原因**：硬件资源不够用。多条指令在同一周期想访问同一块硬件，但硬件只有一个访问口。
- **类比**：一群人抢着用一台打印机。
- **示例**：如果指令内存和数据内存是同一个，那么 IF 阶段取指令和 MEM 阶段访存就会冲突。

**如何解决结构冒险**
RISC-V架构本身就不容易出现某些结构冒险。
- **寄存器堆支持同时读写**：
	1. 在同一个时钟周期内，可以同时进行**写回**和**译码读寄存器**操作。
	2. 这意味着写后读（RAW）场景中，即使读写同时发生，硬件也能正确处理，不会因为寄存器访问冲突而阻塞流水线。
- **内存分成两个独立模块（IMEM 和 DMEM）**：
	**IMEM**：指令内存（用于IF取指阶段）
	**DMEM**：数据内存（用于MEM访存阶段）
	两者分开后，取指令和访问数据可以同时进行，不会争抢同一个内存端口，从而避免了取指和访存冲突这种经典的结构冒险。

假设没有上面这些措施，下面是一些后续的解决方法：
1.**软件方案（时间换正确性——效率低）**：
- **方法**：轮流使用资源，也就是插入**Stall**（停顿）或**NOP**（空操作）。
- **NOP**：即“气泡”，让流水线的一个阶段什么都不做，等冲突解决后再继续。
- **缺点**：虽然能正确解决问题，但浪费了时钟周期，降低了流水线的吞吐率。
2.**硬件方案（成本换效率——昂贵）**：
- **方法**：增加更多硬件资源。比如多开几个访问端口，或者把功能单元复制多份。
- **缺点**：需要更多的芯片面积和功耗，成本较高。
- **优点**：可以从根本上避免冲突，不需要插入停顿，保持流水线满负荷运行。

---
2.**数据冒险**
- **原因**：数据依赖。下一条指令需要的数据，上一条指令还没算出来或还没写回寄存器。
- **类比**：你要用计算器的结果，但计算器还没按等于号。
![[Pasted image 20260303230655.png]]
![[Pasted image 20260303230013.png]]
**方案一：插入气泡（Stall/NOP）**：
- 让流水线**停顿**一个或多个周期，等待上一条指令把结果写回寄存器后，再让下一条指令继续执行。
- 缺点：降低了流水线的效率（吞吐量下降）。
**方案二：数据转发（Data Forwarding）**
- 这是更高效的方案。不需要等待写回寄存器，而是直接将上一条指令计算出的结果，从它所在的阶段（比如EX阶段或MEM阶段）**转发**给下一条指令需要的地方（比如ALU的输入端）。
- 这样就可以绕过寄存器，直接拿到最新值，避免停顿。

---
3.**控制冒险**
- **原因**：流程控制。遇到分支或跳转指令时，在它计算出是否跳转之前，下一条指令已经进入流水线了。那这条已经进来的指令到底该不该执行？
- **类比**：开车遇到岔路口，在看清路标前不知道往哪拐。
- **示例**：`beq` 指令（分支指令）的结果还没算出来，下一条指令已经准备进入流水线了。
![[Pasted image 20260303230154.png]]
**方案一：暂停（Stall）**
- 在遇到分支指令时，让流水线**停顿**一个或多个周期，等待分支结果计算出来，再决定下一条取哪条指令。
- **缺点**：每次遇到分支都要浪费几个周期，影响效率。
**方案二：分支预测（Branch Prediction）**
- 不干等，而是**猜**一个方向继续执行——猜测分支是“跳转”还是“不跳转”。
- 如果**猜对了**：流水线继续满负荷运行，没有浪费周期。
- 如果**猜错了**：需要把已经进入流水线的错误指令**清空（Flush）**，然后从正确的目标地址重新取指，这会造成一定的性能损失。
- 这是现代高性能处理器普遍采用的方法，关键是提高预测的准确率。
# 09-Cache
引入缓存的根本原因——**主存太慢了**。
**速度差距巨大**：
- 访问主存（DRAM）：约需要 **100个** 时钟周期
- 访问L1缓存：约需要 **5个** 时钟周期
- 访问L2缓存：约需要 **30个** 时钟周期
- （访问硬盘：约需要 **10000+** 个时钟周期）
**性能瓶颈**：如果CPU每次访问数据都要等100个周期，那再快的处理器也只能干等着，资源被严重浪费。
**解决方案**：在CPU和慢速主存之间加入**小而快**的缓存，把经常用的数据放在离CPU近的地方，不常用的放在远处（主存），以此平衡速度和容量。

什么样的数据算 ‘ 离得近 ’（应该被缓存）？
答案是两种**局部性原理**：
1. **空间局部性**：
**定义**：靠近当前访问地址的内存位置，在不久后很可能被访问到。
**举例**：程序执行数组遍历时，访问了 `array[0]`，那么 `array[1]`、`array[2]` 很可能马上也会被访问。缓存会一次性把相邻的一块数据都加载进来。
2. **时间局部性**：
**定义**：最近被访问过的内存地址，在不久后很可能再次被访问。
**举例**：循环内的代码或频繁使用的变量，会在短时间内反复执行或读取。缓存会把它们留住，避免反复从主存加载。

**缓存（Cache）的基本术语**：
- **缓存行/块**：CPU与主存之间传输数据的最小单位。也就是一次从主存加载到缓存的数据块大小。
- **组**：由多个缓存行组合成的集合，通过索引来定位。
- **相联度**：每个组里面包含的缓存行数目。它决定了主存中的一个数据块可以放到这个组里的几个不同位置。
- **驱逐**：把数据从缓存中移除（比如当缓存满了，需要腾出空间给新数据时）。

**三种不同类型的缓存结构**：
	主要区别在于**一个数据块能从主存放到缓存中的哪个位置**
1.**直接映射缓存**
- **特点**：限制最严格。主存中的每一个数据块**只能**放到缓存中一个唯一对应的位置。
- **优点**：硬件实现最简单、速度最快。
- **缺点**：如果程序反复访问两个映射到同一位置的数据，就会频繁相互驱逐，导致命中率下降。
2.**全相联缓存**
- **特点**：限制最宽松。主存中的任何一个数据块可以放到缓存中的**任意一个位置**。
- **优点**：放置策略最灵活，理论上冲突率最低。
- **缺点**：硬件实现最复杂、成本最高、查找速度慢（需要比较所有行），通常只用于非常小的缓存（如TLB）。
3.**N路组相联缓存**
- **特点**：前两者的折衷方案。缓存被分成若干组，每组有N个缓存行。主存中的数据块可以放到**指定组中的任意一个位置**。
- **优点**：在硬件复杂度、成本和命中率之间取得了很好的平衡，是现代CPU最常用的方式。

**补充注释**： **重要**
- **直接映射** 可以看作是 **1路组相联**（每组只有1行）。
- **全相联** 可以看作是 **M路组相联**，其中 M 等于缓存的总行数（也就是整个缓存只有一个组）。

---
**缓存地址结构**中非常重要的**TIO划分** -- 也就是如何将一个CPU发出的内存地址，拆解成**Tag（标签位）、Index（索引位）、Offset（偏移位）** 三个部分。
**Tag（标签位）：**
- 内存地址的**高位部分**（`MSB，Most Significant Bits`）。
- 作用：**唯一标识**这个数据块来自主存中的哪个区域。当CPU在缓存中找到了可能的行（通过Index），需要用Tag来确认这一行里放的到底是不是CPU想要的那个数据。
**Index（索引位）**：
- Tag后面的**中间位**。
- 作用：用来选择（索引）到缓存中的**具体某一组**。CPU拿着这个Index，直接找到对应的那一组缓存行。
**Offset（偏移位）**：
- 内存地址的**低位部分**。
- 作用：在一个缓存块内部，定位到具体的**某一个字节**或字。因为一次加载进缓存的是一个块（包含多个字节），Offset用来从中挑出CPU当前需要的那个字节。

**缓存替换策略**（Eviction Policies），
即当缓存满了，需要腾出空间加载新数据时，应该**驱逐（Evict）哪一块数据**。
**LRU（最近最少使用）**
- **策略**：驱逐在当前组中，**最久没有被访问过**的那一块。
- **逻辑**：既然很久没用，那可能以后也不太需要。
**MRU（最近最常使用）**
- **策略**：驱逐在当前组中，**最近被访问过**的那一块。
- **逻辑**：在某些特殊循环模式下，刚用过的可能接下来最久不会再用。
**FIFO（先进先出）**
- **策略**：驱逐在缓存组中**停留时间最长**的那一块（像一个队列）。
- **逻辑**：谁先进来，谁先出去，不管它被访问的频率。
**LIFO（后进先出）**
- **策略**：驱逐**最新进入**缓存的那一块（像一个栈）。
- **逻辑**：刚来的先走。
**Random（随机）**
- **策略**：随机选一块驱逐。
- **优点**：硬件实现非常简单。

**为什么没有“最好”的策略？？？**
1. **衡量标准不同**：“最好”指的是什么？是**命中率最高**（效率），还是**电路最简单**（实现成本），还是**功耗最低**（可靠性）？不同目标指向不同策略。
2. **程序行为不同**：某种策略在程序A上表现优异，但在程序B上可能恰巧是最差选择。
3. **数据集不同**：即使是同一个程序，处理不同的数据集时，最优策略也可能发生变化。
# 10-`Multi-Level Caches，AMAT`
**CPU访问缓存时的一次完整工作流程**
**第一步：地址分解**
- CPU发出的内存地址，按照之前讲过的**TIO原则**，被拆分成：**Tag（标签）、Index（索引）、Offset（偏移）**。
**第二步：定位到组并检查有效性**
- 用**Index**找到缓存中对应的那一组。
- 检查这一组里有没有**有效的缓存行**（Valid Entry）？
    1.**如果没有有效行**（缓存缺失的开始）：直接跳转到**第四步**（从内存加载）。 
    2.**如果有有效行**：进入第三步，进行标签比对。
**第三步：标签比对**
在独立的标签存储器中，拿地址的**Tag**部分，和这一组里缓存行携带的Tag进行比较，看是否匹配？
- **如果Tag匹配**（缓存命中）：恭喜！跳转到**第五步**，直接读取数据。
- **如果Tag不匹配**（确实是缓存缺失）：检查这一组里**还有没有空闲位置**？
	1.**如果有空闲**：跳转到第四步（加载数据到空闲行）。
    2.**如果没有空闲**：根据**替换策略**（如LRU、随机等），先踢出去一个旧的，腾出位置，然后跳转到第四步。
**第四步：从主存加载**
- 当缓存中没有找到需要的数据时，从慢速的**主存（Memory)** 中把包含这个数据的整个块（Block）加载到缓存里来。
**第五步：返回数据**
- 最后，利用地址中的**Offset**位，从已经加载到缓存的块中，提取出CPU需要的那个具体的字节或字，返回给CPU。

缓存未命中（Cache Misses）
1.强制性未命中
- **原因**：这是程序第一次访问某个数据块，这个数据块**从未被加载进缓存**过。
- **特点**：不可避免，一定会发生。
- **优化方向**：可以通过**增大块大小**来减少强制缺失。因为块越大，一次加载的数据越多，后续访问相邻数据时就更容易命中。
2.冲突未命中
- **原因**：缓存**组相联度有限**导致的。由于多个不同的内存块映射到了缓存中的**同一组**，导致之前的数据被踢了出去。等再次需要它时，发现已经不在了。
- **判断方法**：如果缓存是全相联的，这种缺失就不会发生。
- **优化方向**：可以通过**提高相联度**（比如从2路变成4路）或者**改进替换策略**（比如用LRU替换随机策略）来减少冲突缺失。
3.容量未命中
- **原因**：缓存**太小了**，装不下程序当前工作所需的所有数据。导致某个数据块被加载进来后，又因为空间不够而被踢出，下次用的时候需要重新加载。
- **判断方法**：即使在全相联缓存中，这种缺失依然会发生，因为它不是映射冲突导致的，纯粹是容量不够。
- **优化方向**：只能通过**增大缓存总容量**来解决。

Average Memory Access Time，**AMAT（平均内存访问时间）**，
	量化了CPU每次访问内存时平均需要花费多少个周期，是评估缓存子系统性能的重要工具。
![[Pasted image 20260304113618.png]]
**Hit Time（命中时间）**
- 在缓存中**命中**时，访问数据所需要的时间。也就是从发出地址到拿到数据之间的延迟。这个时间通常很短（几个时钟周期）。
**Miss Rate（缺失率）**
- 这里特别标注了是**局部缺失率**。也就是在缓存中没有找到数据的概率（例如 $Miss Rate=MissesTotal AccessesMiss Rate / Total AccessesMisses​$）。
**Miss Penalty（缺失惩罚）**
- 当缓存**缺失**时，需要额外付出的代价。具体取决于内存层次结构：
- **对于单级缓存**：缺失惩罚就是直接访问**主存**所需的时间。
- **对于多级缓存**（如L1、L2、L3）：缺失惩罚的计算会更复杂，需要递归地代入下一级缓存的AMAT。例如，L1缓存缺失后，需要访问L2缓存，那么此时的缺失惩罚就是L2缓存的平均访问时间（即 L2 的 AMAT）。
# 11-Parallelism,Coherency,and Atomic
**数据级并行**的一种具体实现形式——**SIMD（单指令多数据）**

**1.什么是 SIMD**
- **全称**：Single Instruction, Multiple Data（单指令多数据）
- **核心思想**：**一条指令**同时作用于**多个数据**上。
- **类比**：就像体育老师喊了一声“向右转”（一条指令），全班的同学（多个数据）同时执行这个动作。不需要老师挨个喊“张三转”、“李四转”。
- **作用**：特别适合处理大量数据的情况，比如图像处理、音频编码、科学计算等。
**2.SIMD 寄存器**
- PPT 中列举了例子：`__mm256d` 和 `__m256i`
- **重要提示**：幻灯片特别强调这些**不是数据类型，而是寄存器**。
    `__mm256d`：这是一个 256 位宽的寄存器，可以用来存放 **4 个 64 位双精度浮点数**。
    `__m256i`：这也是一个 256 位宽的寄存器，可以用来存放 **8 个 32 位整数**。
- 这意味着 CPU 可以一次性把一个 256 位的大寄存器装满数据，然后用一条指令同时处理里面的所有数据。
**3.SIMD 指令命名规则**
格式：`<寄存器大小>_<指令>_<组件类型>`
**例子**：`__mm256_add_epi32`
- `__mm256`：表示这是一个 256 位的寄存器操作。
- `add`：表示执行加法操作。
- `epi32`：表示将寄存器里的内容视为 32 位整数（每个 32 位，一共 8 个）来进行加法。
[`Intel Intrinsics Guide`](https://www.intel.com/content/www/us/en/docs/intrinsics-guide/index.html),可以查到所有 SIMD 指令的具体用法。

**线程级并行**

1.什么是线程
- **定义**：线程是一个**顺序执行**的指令流，用于执行特定任务。
- **关键特征**：同一个进程中的多个线程**共享内存空间**。这意味着线程之间可以通过读写同一块内存区域来进行通信和数据交换。

2.OpenMP 简介
OpenMP 是一种用于共享内存并行系统的多线程程序设计模型。PPT 主要列举了几个最常用的指令和函数：
- **`#pragma omp parallel`**：
	这是 OpenMP 的基础指令。它后面的代码块会被多个线程**并行执行**。
    简单来说，如果不加任何修饰，每个线程都会完整地执行一遍这个代码块。
- **两个常用 API 函数**：
	`omp_get_num_threads()`：返回当前并行区域中**活跃的线程总数**。
    `omp_get_thread_num()`：返回当前线程的**唯一编号**（一个从 0 到 `num_threads-1` 的整数）。这常用于让不同线程处理不同的数据，比如根据线程号分配任务。
- **数据共享属性**：
	`#pragma omp parallel private(var) shared(var2)`：
	`private(var)`：指明变量 `var` 在每个线程中都有一个**私有的副本**，线程之间互不干扰。
    `shared(var2)`：指明变量 `var2` 在**所有线程间是共享的**（只有一个副本，所有线程都能访问）。

3.并行 for 循环
**`#pragma omp parallel for`**：
- 这是一个非常实用的指令，专门用于并行化循环。
- 它会自动将循环的**不同迭代分配给不同的线程执行**。
- 例如，如果循环有 100 次迭代，有 4 个线程，那么每个线程可能会被分配执行大约 25 次迭代。

**缓存的写策略**，也就是当 CPU 执行写操作时，缓存系统如何处理数据一致性的问题。
分成两种情况来讨论：**写命中**（要写的数据已经在缓存里）和**写缺失**（要写的数据不在缓存里）。

1.写命中时的三种策略
**Write-through（写通/直写）**
- **做法**：同时写入**缓存块**和**主存**。
- **特点**：实现简单，能保证主存中的数据永远是最新的（一致性高），但每次写操作都要访问慢速的主存，性能较差，带宽占用高。
**Write-back（写回）**
- **做法**：只写入**缓存块**，并标记该块为“脏”（dirty）。只有当这个缓存块被**驱逐**（evict）出缓存时，才将数据一次性写回主存。
- **特点**：减少了频繁的主存访问，性能较高。但实现更复杂，需要脏位（dirty bit）来记录块是否被修改过。
**Write-around（绕写）**
- **做法**：绕过缓存，直接写入**主存**。
- **特点**：通常用于避免缓存被大量写入数据污染（比如写入流媒体数据时，避免占满缓存），但下一次读这些数据时会因为不在缓存中而发生缺失。

2.写缺失时的两种策略
当 CPU 要写入的数据不在缓存中时，有两种处理方式：
**Write-allocate（写分配）**
- **做法**：先将缺失地址所在的整个内存块**加载到缓存中**，然后再在缓存中执行写入操作。
- **特点**：结合 **Write-back** 使用效果较好。下次再访问这个地址时，数据已经在缓存里了。
**No-write-allocate（非写分配）**
- **做法**：不将数据加载到缓存，而是直接**写入主存**。
- **特点**：通常与 **Write-through** 搭配使用。适用于不需要重复写入的场景，避免不必要的缓存加载。

虽然这几种策略可以独立选择，但在实际硬件实现中，通常有两种固定搭配：
1. **Write-through + No-write-allocate**：写操作直接过缓存写内存，且不加载缺失的块（因为后续可能不再需要）。
2. **Write-back + Write-allocate**：先加载后写缓存，等驱逐时再写回内存（利用局部性，减少主存访问）。

**缓存一致性**
之前学到的内容从单核（流水线、冒险、缓存结构）过渡到多核（线程级并行），现在面临的挑战是：**当多个核心都有自己的缓存时，如何保证它们看到的数据是一致的？**

**1.背景：每个核心拥有独立缓存**
- 在多核处理器中，**每个核心都包含自己私有的缓存**（如L1缓存）。
- 这就意味着，同一个内存地址的数据，可能同时在多个核心的缓存中都存在副本。

**2.核心机制：缓存块的状态**
为了解决一致性问题，每个缓存块不再只是简单的数据和标签，还携带了一个**状态**。
PPT中提到了用于表征状态的三个关键位：**Valid（有效位）**、**Dirty（脏位）**、**Shared（共享位）**。通过这些位的组合，可以定义出不同的状态，比如：
- **Modified**：该块已被修改，且只存在于当前缓存（其他缓存没有），与主存不一致。
- **Exclusive**：该块与主存一致，且只存在于当前缓存。
- **Shared**：该块与主存一致，且可能存在于多个缓存中。
- **Invalid**：该块无效（相当于不存在）。
这些状态的作用是：**帮助缓存判断当前这个块与其他核心中的副本相比，处于什么关系**。是唯一的？被修改过？还是干净的共享数据？

**3.通信基础：互联网络**
- 要让不同核心的缓存之间协调状态，不能每次都去访问慢速的主存。
- **互联网络**用于各个缓存之间直接通信。当一个核心修改了某个数据，它可以通过这个高速网络通知其他核心：“你们手里的那个副本已经过期了”，这个过程称为**监听（Snooping）**或基于目录的协议，而无需立即更新主存。

为缓存一致性协议（如 MSI、MESI、MOESI 等）打下了基础。核心思想是：**通过给每个缓存块附加状态位，并利用互联网络让缓存之间可以直接沟通，从而在硬件层面自动维护多份数据副本的一致性，保证程序正确运行。**

---
**缓存一致性中的基础术语** & **整个系统的层级结构** 
1.三个核心术语的定义
**Dirty bit（脏位）**：
- **作用**：标记这个缓存块是否被**修改过**。
- **含义**：如果脏位为1，说明CPU已经改过这个缓存块里的数据，但现在**主存里的数据还是旧的、没更新**。等到这个块被驱逐（Evict）时，必须把数据写回主存。
**Valid bit（有效位）**：
- **作用**：标记这个缓存块是否**有效**。
- **含义**：简单来说，就是“这个缓存块里存的数据能不能用”。如果有效位为0，即使索引和标签匹配，也算**缺失（Miss）**。刚启动时所有有效位都是0，加载数据后才置为1。
**Shared bit（共享位）**：
- **作用**：标记这个缓存块是否在**多个核心的缓存**中都存在副本。
- **含义**：用于多核通信。如果共享位为1，说明其他核心可能也在用这份数据，当前核心修改时需要通知它们。

2.系统层级结构
![[Pasted image 20260304151410.png]]
- **Processor（处理器核心）**：最接近CPU运算单元的位置。
- **Cache（缓存）**：每个核心私有的高速缓存。
- **Interconnection Network（互联网络）**：这是**多核通信的骨干**。各核心的缓存通过它来传递一致性消息（比如“我要修改这个数据，你们把副本标记为无效”），而不必每次都经过主存。
- **Memory（主存）**：慢速的共享内存，是所有数据的最终归宿。
- **I/O（输入输出）**：连接外部设备。

原子操作
- **定义**：原子操作是指一个**不可中断**的操作。要么全部执行完，要么完全不执行，中间不会被其他线程或核心打断。
- **为什么需要**：在多核环境下，如果两个核心同时读取然后写入同一个变量，可能会导致数据出错（比如经典的“i++”问题）。原子操作保证了这种“读-改-写”的过程是连续的、不可分割的。

两种实现方式
**Amoswap（原子内存交换）**
- **特点**：一条指令就能完成**不可中断**的内存操作。
- **作用**：它将寄存器的值和内存地址的值交换，整个过程不会被其他核心打断。常用于实现简单的锁（mutex）。
**Load-reserve / Store-conditional（加载保留/条件存储）**
- **特点**：允许在**多条指令**之间实现不可中断的操作（比如需要先读、判断、再写的复杂操作）。
- **工作原理**：
	1. **Load-reserve（加载保留）**：特殊地加载一个内存地址，并监视该地址。
    2. **Store-conditional（条件存储）**：尝试写入。如果在此期间没有其他核心修改过这个地址，写入成功；否则写入失败，需要重试。

示例代码解析
典型的“测试并设置锁”的代码，用 `amoswap` 实现自旋锁
```
Start: 
    addi t0 x0 1          # t0 = 1 (表示“锁被占用”)
    amoswap.w.aq t1 t0 (a0) # 原子交换：将 t0(1) 写入内存(a0)，并将原来的值读到 t1
    bne t1 x0 Start       # 如果原来的值 t1 不是 0 (说明锁之前已被占用)，则跳回 Start 重试
    ...                   # 临界区（Critical section）：此时成功获得锁，执行需要保护的操作
    # 释放锁（通常是将内存(a0)的值写回0）
```
**这段代码的逻辑是**：
1. 尝试把 `1` 写入锁变量地址 `(a0)`。
2. `amoswap` 指令会原子地完成“读旧值→写新值”的过程，并返回旧值到 `t1`。
3. 如果返回的旧值是 `0`，说明之前锁是空闲的，当前线程成功获得锁，进入临界区。
4. 如果返回的旧值是 `1`，说明锁已被别人占用，则跳回 `Start` 不断重试，直到成功为止。
